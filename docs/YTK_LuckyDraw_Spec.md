# YTK Lucky Draw 抽奖系统 — 开发规格书 v1(给 Claude Code)

> 附件 `YTK_LuckyDraw_Prototype.html` 是已经确认过的前端原型(手机/iPad 实测过版面)。**动画、音效、版面、手感以它为准,不要重新设计**。本规格书要做的是:把它变成可以在后台调整设置、由服务器决定奖品并扣库存的正式系统,并部署到 YTK 的 VPS。

---

## 1. 这是什么

YTK 店内使用的抽奖系统。客人单笔消费满 RM100 可抽一次,在店里的 iPad 上点击抽奖:礼盒抖动 → 盖子弹开 → 光线涌出 → 白光闪过 → 弹出奖品 popup,同时播放 "Y~T~K~" 合唱音效。

两个界面:
- **客人界面 `/`**:iPad 全屏展示,客人只能点击抽奖。看不到任何设置、奖品清单、中奖率。
- **后台 `/admin`**:YTK 管理员登录后调整所有设置、管理奖品和库存、查看抽奖记录。

## 2. 架构(沿用 YTK 既有原则)

- **独立系统**:独立 GitHub repo(建议名 `ytk-lucky-draw`),独立数据库,**不要**把表放进 Quotation System 或 HR System 的 Supabase 项目里。
- **技术栈**:Next.js + Supabase(Auth + Postgres),与 Quotation System 一致。
- **测试环境**:使用已有的共享测试 Supabase 项目 `ytk.tech`。
- **正式环境的 Supabase 项目**:**待 EKHAN 决定**(抽奖数据敏感度低,可能与 Quotation 正式项目共用,以省每月 US$10 的 compute 费用;也可按"每个系统独立正式项目"的原则另开)。**在他确认之前不要创建新的正式项目**,先用测试项目开发和测试。
- **VPS**:YTK 自己的 VPS(187.53.136.173),与 Quotation System 同机,但**独立的 pm2 进程 + 独立端口 + 独立 nginx server block + certbot HTTPS**。
- **域名**:建议正式 `draw.ytkholding.com`、测试 `draw.aido.works`(**待 EKHAN 确认**)。
- **部署**:GitHub Actions,沿用 Quotation System 的 rsync 部署方式;GitHub Secrets 用独立命名(例如 `YTK_DRAW_VPS_*`),**不要覆盖**现有的 `YTK_VPS_*`。SSH 密钥规则不变:私钥不在聊天里粘贴,按之前约定的流程处理。

## 3. 后台可调整的设置(客人看不到)

所有设置存数据库,客人界面每次加载时读取,另外每隔 5 分钟和每次抽奖完成回到待机画面时刷新一次,所以后台改了之后 iPad 不用重装、不用手动刷新。

### 3.1 文字
| 设置 | 原型中的位置 | 默认值 |
|---|---|---|
| 标题第一行 | 大字红色 | `YTK` |
| 标题第二行(副标) | 金色 | `LUCKY DRAW` |
| 说明文字 description | 标题下的小字 | `Spend RM100 or more in one bill to draw once` |
| 按钮文字 | 底部金色按钮 | `TAP TO OPEN` |
| 中奖 popup 提示语 | popup 底部 | `Show this screen to the cashier` |

(标题两行的颜色也做成可选设置,默认保持现在的红 / 金。)

### 3.2 颜色
- **背景渐层**:2 到 3 个色标(color stop),每个有颜色选择器;可调渐层角度。后台旁边要有**即时预览**。
  - 默认:深藏青 `#141A26` → `#1E2430`,底部带一点红色光晕(见原型 `.bg`)。
- **礼盒两个颜色**:
  - 盒身 / 盖子颜色(默认黄 `#F5C242`)
  - 丝带 / 蝴蝶结颜色(默认红 `#E14B4B`)
  - 原型里的渐层和阴影色阶,**由这两个颜色自动计算出来**(浅一阶、深一阶),管理员只选两个颜色,不需要自己配渐层。
- 光线和光晕颜色:默认金色,跟着盒身颜色自动推导(可不开放设置)。
- 要有 "恢复默认" 按钮。

### 3.3 声音
- 音效总开关
- 合唱 "Y-T-K" 开关
- (预留)`choir_audio_url`:若填了音频文件,播放该文件代替程序合成的合唱。以后 EKHAN 如果拿到真人录音,上传即可替换,不需改代码。

### 3.4 奖品管理
每个奖品字段:

| 字段 | 说明 |
|---|---|
| 名称 | 例如 `RM50 Purchase Voucher` |
| 等级标签 | 例如 `GRAND PRIZE`、`1ST PRIZE`、`LUCKY GIFT`,显示在 popup 顶部的小标签 |
| 标签颜色 | 每个奖品可选(原型里不同等级颜色不同) |
| **库存数量 stock** | 整数。**允许留空 = 无限量**(用于安慰奖) |
| **权重 weight** | 整数,相对值,**不是**百分比 |
| 启用 / 停用 | 停用的奖品不会被抽中 |
| 排序 | 仅用于后台列表显示 |

后台奖品列表要显示:
- 每个奖品**目前实际中奖概率** = 该奖品权重 ÷ 所有「已启用且库存 > 0」奖品的权重总和。库存用完的奖品概率显示 0,其余自动重新分配。
- 剩余库存、已中奖数量。
- 快速 "补货" 按钮(+N)。
- 库存低于可设定门槛时,列表上高亮提示。

### 3.5 抽奖规则
- **抽中后立即扣库存**,在服务器端、同一个数据库事务内完成(见第 4 节)。
- **所有奖品都抽完时**:客人界面不能出错或卡住。后台可设置一段 "奖品已抽完" 的提示文字,以及可选的一个无限量安慰奖。

## 4. 抽奖逻辑(必须在服务器端)

**绝对不能在浏览器里随机**,否则客人刷新页面或截图就能重抽,也无法保证库存正确。

流程:
1. 客人点击 → 前端生成一个 `draw_token`(UUID),`POST /api/draw`。
2. 服务器在**一个事务内**:
   - 查询所有 `active = true` 且 (`stock IS NULL` 或 `stock > 0`) 的奖品;
   - 按权重加权随机抽出一个;
   - 对有限库存奖品执行 `UPDATE ... SET stock = stock - 1 WHERE id = ? AND stock > 0`,并检查受影响行数(防止两台 iPad 同时抽到最后一个);失败则重新抽;
   - 写入 `draws` 记录;
   - 返回奖品的名称、等级、颜色。
3. **幂等**:同一个 `draw_token` 重复请求,返回**同一个**结果,不重复扣库存(应对网络重试)。
4. 前端**在点击的同时**发出请求,动画播放期间等待结果;若结果在闪白前还没回来,动画保持在光芒阶段等待(原型里已有这个等待逻辑)。若请求失败,显示友好的错误提示并回到待机画面,**不扣库存、不记录**。
5. 奖品权重、库存、概率**不下发到客人浏览器**。

建议用 Postgres function(RPC)实现抽奖事务,用 `FOR UPDATE` 或条件更新保证原子性。给 `/api/draw` 加简单限流。

---

## 5. 数据表(建议,可由 Claude Code 调整)

- `draw_settings`:单行配置(文字、颜色、声音开关、门槛等)。
- `prizes`:id, name, tier_label, tier_color, stock(nullable), weight, active, sort_order, created_at。
- `draws`:id, draw_token(unique), prize_id, prize_name(**快照**,日后改名不影响历史), tier_label, created_at, kiosk_id(可选)。
- `admin_users`:沿用 Supabase Auth,只有管理员角色能进 `/admin`、能写入设置和奖品。
- 所有表开启 RLS。客人界面只通过服务器 API 取设置和抽奖,**不直接读 `prizes` 表**。

后台再加一个页面:**抽奖记录**,可按日期、奖品筛选,可导出 CSV;并显示各奖品今日 / 累计中奖数。

## 6. 客人界面(iPad)要求

- 以附件原型为准:动画时间线、礼盒 SVG、彩带 / 火花粒子、白光闪过、popup、合唱音效,**保持不变**。礼盒颜色和背景改成从设置读取。
- **原型里右上角的 "Prototype" 面板(指定奖品、静音、合唱开关)必须从客人界面移除**。客人界面不能有任何入口能看到奖品或概率。
- 后台里做一个 "测试模式" 预览:可以看动画效果、指定下一个奖品来预览 popup,但**不扣库存、不写入抽奖记录**。
- 整个页面锁定为一屏,不能上下左右滑动(原型已处理);禁用双击缩放、长按选取。
- iPad 注意事项:
  - 声音必须由点击触发(浏览器规定),原型已处理。
  - 加入主屏幕(PWA)的全屏模式 meta 设定,客人看不到浏览器地址栏。
  - 使用 Screen Wake Lock,避免 iPad 抽奖途中自动休眠;不支持时安静降级。
  - 网络中断时:待机画面仍可显示,点击后给出友好提示,不要白屏。
- 手机竖屏、手机横屏、iPad 横 / 竖屏都要看一遍(原型在 390×664、390×780、375×560、740×360 量过,按钮和 popup 都在画面内)。
